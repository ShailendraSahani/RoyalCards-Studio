# Database Schema Documentation

## Overview
The Online Marriage Card Booking System uses MongoDB as the primary database with Mongoose ODM for schema definition and data validation. The database is designed with a normalized structure to maintain data integrity and optimize query performance.

## Collections

### 1. Users Collection
**Collection Name:** `users`

**Schema:**
```javascript
{
  _id: ObjectId, // Auto-generated by MongoDB
  name: {
    type: String,
    required: true,
    trim: true
  },
  email: {
    type: String,
    required: true,
    unique: true,
    lowercase: true,
    trim: true
  },
  password: {
    type: String,
    required: true,
    minlength: 6
  },
  role: {
    type: String,
    enum: ['user', 'admin'],
    default: 'user'
  },
  createdAt: {
    type: Date,
    default: Date.now
  },
  updatedAt: {
    type: Date,
    default: Date.now
  }
}
```

**Indexes:**
- `{ email: 1 }` (unique)
- `{ role: 1 }`
- `{ createdAt: -1 }`

**Relationships:**
- Referenced by: orders, customizations, cart items, card designs

### 2. Card Designs Collection
**Collection Name:** `carddesigns`

**Schema:**
```javascript
{
  _id: ObjectId,
  name: {
    type: String,
    required: true,
    trim: true
  },
  description: {
    type: String,
    required: true
  },
  category: {
    type: String,
    enum: ['traditional', 'modern', 'elegant', 'fun', 'custom'],
    default: 'traditional'
  },
  templateImage: {
    type: String,
    required: true // URL or base64 encoded image
  },
  price: {
    type: Number,
    required: true,
    min: 0
  },
  isActive: {
    type: Boolean,
    default: true
  },
  createdBy: {
    type: ObjectId,
    ref: 'User',
    required: true
  },
  createdAt: {
    type: Date,
    default: Date.now
  },
  updatedAt: {
    type: Date,
    default: Date.now
  }
}
```

**Indexes:**
- `{ category: 1, isActive: 1 }`
- `{ createdBy: 1 }`
- `{ createdAt: -1 }`
- `{ price: 1 }`

**Relationships:**
- References: User (createdBy)
- Referenced by: orders, customizations

### 3. Customizations Collection
**Collection Name:** `customizations`

**Schema:**
```javascript
{
  _id: ObjectId,
  user: {
    type: ObjectId,
    ref: 'User',
    required: true
  },
  cardDesign: {
    type: ObjectId,
    ref: 'CardDesign',
    required: true
  },
  canvasData: {
    type: Object, // Fabric.js canvas JSON data
    required: true
  },
  previewImage: {
    type: String // Base64 encoded preview image
  },
  isSaved: {
    type: Boolean,
    default: false
  },
  createdAt: {
    type: Date,
    default: Date.now
  },
  updatedAt: {
    type: Date,
    default: Date.now
  }
}
```

**Indexes:**
- `{ user: 1, createdAt: -1 }`
- `{ cardDesign: 1 }`
- `{ isSaved: 1 }`

**Relationships:**
- References: User, CardDesign
- Referenced by: cart items, orders

### 5. Orders Collection
**Collection Name:** `orders`

**Schema:**
```javascript
{
  _id: ObjectId,
  user: {
    type: ObjectId,
    ref: 'User',
    required: true
  },
  cardDesign: {
    type: ObjectId,
    ref: 'CardDesign',
    required: true
  },
  customization: {
    type: ObjectId,
    ref: 'Customization',
    required: true
  },
  quantity: {
    type: Number,
    default: 1,
    min: 1
  },
  totalPrice: {
    type: Number,
    required: true,
    min: 0
  },
  status: {
    type: String,
    enum: ['pending', 'paid', 'processing', 'shipped', 'delivered', 'cancelled'],
    default: 'pending'
  },
  paymentId: {
    type: String // Razorpay payment ID
  },
  shippingAddress: {
    name: { type: String, required: true },
    address: { type: String, required: true },
    city: { type: String, required: true },
    state: { type: String, required: true },
    zip: { type: String, required: true },
    phone: { type: String, required: true }
  },
  createdAt: {
    type: Date,
    default: Date.now
  },
  updatedAt: {
    type: Date,
    default: Date.now
  }
}
```

**Indexes:**
- `{ user: 1, createdAt: -1 }` (compound)
- `{ status: 1 }`
- `{ createdAt: -1 }`
- `{ paymentId: 1 }`

**Relationships:**
- References: User, CardDesign, Customization

### Key Relationships

1. **User → CardDesign** (1:N)
   - One user can create multiple card designs
   - Admin users primarily create designs

2. **User → Customization** (1:N)
   - One user can have multiple customizations
   - Each customization belongs to one user

3. **CardDesign → Customization** (1:N)
   - One card design can have multiple customizations
   - Each customization is based on one card design

4. **User → Cart** (1:N)
   - One user can have multiple cart items
   - Cart items are temporary until checkout

5. **User → Order** (1:N)
   - One user can place multiple orders
   - Orders are permanent transaction records

6. **Customization → Cart** (1:1)
   - Each cart item references one customization
   - Customizations can exist without being in cart

7. **Customization → Order** (1:1)
   - Each order references one customization
   - Orders are created from cart items

## Data Validation Rules

### User Validation
- Email must be unique and valid format
- Password minimum 6 characters
- Role must be either 'user' or 'admin'
- Name cannot be empty

### Card Design Validation
- Name and description required
- Price must be positive number
- Category must be from predefined list
- Template image URL required
- Created by must reference valid user

### Customization Validation
- User and card design references required
- Canvas data must be valid JSON object
- Preview image optional but recommended

### Cart Validation
- User and customization references required
- Quantity must be positive integer
- Total price calculated automatically

### Order Validation
- All references (user, card design, customization) required
- Quantity must be positive integer
- Status must be from predefined enum
- Shipping address must have all required fields
- Total price must be positive

## Indexing Strategy

### Performance Indexes
1. **Users Collection:**
   - Email index for authentication
   - Role index for admin queries
   - Created date for user analytics

2. **Card Designs Collection:**
   - Category + active status for filtering
   - Price index for sorting
   - Creator index for admin management

3. **Customizations Collection:**
   - User + date for user customization history
   - Card design for template analytics

4. **Cart Collection:**
   - User + date for cart management
   - Customization for duplicate prevention

5. **Orders Collection:**
   - User + date for order history
   - Status for order management
   - Payment ID for payment verification

### Compound Indexes
- `{ user: 1, createdAt: -1 }` on multiple collections for user-specific queries
- `{ category: 1, isActive: 1 }` for active card filtering
